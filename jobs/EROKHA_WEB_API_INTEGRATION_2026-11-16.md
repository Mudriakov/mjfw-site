# Подключение веб-чата Ерохи к HTTPS API

**Дата:** 16 ноября 2026 г.  
**Репозиторий:** `Mudriakov/mjfw-site`  
**API base URL:** `https://api.mudriakov.ru`  
**Область изменений:** только статический сайт на GitHub Pages, без изменений VPS, Docker, PostgreSQL и бота.

## Выполнено

1. В `index.html` (строка 364 на момент изменения) у скрипта `/assets/js/erokha-chat.js?v=3` установлен `data-erokha-api="https://api.mudriakov.ru"`. Базовый адрес не содержит `/v1`.
2. В `assets/js/erokha-chat.js` сохранены существующие дизайн, логика отображения чата и RU/EN-переключение по `document.documentElement.lang`.
3. Создание сеанса: `POST /v1/session`, языки `ru/en`, сохранение токена в `sessionStorage["erokha_session_v1"]`. Повторное открытие виджета использует существующий токен; одновременная инициализация защищена одним Promise.
4. История: `GET /v1/history`, `X-Eroha-Session`, роли `user/assistant/developer` и безопасный рендеринг текста через текстовые DOM-узлы. История перерисовывается только при изменении; дубли не дописываются.
5. Сообщение: `POST /v1/message`, UUID через `crypto.randomUUID()`, лимит 4000 символов, поддержка статусов `done/processing`, индикация ожидания. При повторе после ошибки сохраняются исходные `request_id`, текст и язык. Черновик хранится в `sessionStorage["erokha_draft_v1"]`.
6. Приём ответа: опрос истории раз в 5 секунд при открытом чате; пауза в скрытой вкладке; запрет параллельных опросов; ожидание сообщения `assistant` после отправленного сообщения.
7. Заявка: `POST /v1/contact` только при явном согласии посетителя (чекбокс первоначально выключен), лимиты сообщения 2500 символов и контакта 300 символов. Статус `queued` объясняется как «принято для передачи», без обещания немедленного ответа.
8. Обработка `401`: очистка устаревшего токена и истории, новая сессия без автоматической повторной отправки обращения. `409`: остановка повторов, уведомление о конфликте. `429`: интервал ожидания 30 секунд без автоматических повторов отправки. Сетевые и серверные ошибки сохраняют текст для ручного повтора.
9. Для запросов используются `mode:"cors"`, `credentials:"omit"`, `cache:"no-store"`, `Content-Type:"application/json"`, таймаут 90 секунд.
10. Визуальные стили `assets/css/erokha-chat.css`, аватар `/assets/images/erokha-avatar.png`, основной `assets/js/i18n.js` и карточки портфолио не менялись.

В частности проверены адрес API, путь скрипта и cache busting, пути и заголовки HTTP, хранение токена, четыре endpoint, UUID, лимиты, статусы асинхронного ответа, повторы, видимость страницы, безопасный рендеринг, поддержка RU/EN и неизменность подключенных CSS/аватара.

- Реальное создание сеанса браузером на `https://mudriakov.ru` и CORS preflight.
- Живые диалоги на русском и английском с OpenAI.
- Наличие сообщений после перезагрузки страницы в реальном браузере.
- Ответ Ивана через Telegram и его появление в веб-чате.

- Мобильный визуальный осмотр на iPhone/Android.
- HTTPS и DNS были недоступны из рабочего контейнера; внешний веб-загрузчик также не смог открыть `/health` или сайт. Предоставленное владельцем сообщение о `/health: {"status":"ok"}` не заменяет эти проверки.

## Рекомендованная браузерная приёмка

1. Открыть `https://mudriakov.ru` и DevTools -> Network.
2. Нажать на круглую аватарку Ерохи в правом нижнем углу.
3. Проверить успешный `POST https://api.mudriakov.ru/v1/session` (201), затем `GET /v1/history` с `X-Eroha-Session`.
4. Отправить вопрос на русском и убедиться, что ответ появился в истории без дублей.
5. Переключить RU/EN на сайте и провести отдельный вопрос на английском.
6. Обновить страницу в той же вкладке; убедиться в сохранении истории.
7. Проверить отправку обращения только после установки чекбокса согласия; успешный `202 queued` означает постановку в очередь, а не прочтение Иваном.
8. Ответить на заявку из Telegram владельца и убедиться в появлении роли `developer` в веб-истории.
9. Открыть сайт в независимом профиле браузера и убедиться, что чужая история не отображается.
10. Проверить размеры 390 px и 320 px, клавиатуру смартфона, сворачивание/разворачивание и ошибку отключённой сети.
11. При CORS/5xx ошибке исправлять соответствующую конфигурацию серверного API отдельно, не отключать CORS на сайте.

## Известные ограничения

- Публичная API-интеграция опубликована в коде, но сквозное поведение ещё требует проверки браузером с реальным доступом к серверу.
- Из этого рабочего окружения нет доступа к VPS и Telegram владельца, поэтому заявлять об успешной передаче заявки или ответе владельца нельзя.
- Обработка асинхронного ответа предполагает, что /v1/history выдаёт последовательность ролей с сохранением нового user-сообщения и последующего assistant-ответа, как описано в контракте.
