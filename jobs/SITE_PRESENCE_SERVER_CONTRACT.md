# Онлайн-посетители сайта mudriakov.ru

Дата: 16 ноября 2026.

## Статус

Фронтенд счётчика добавлен в сайт. Серверный endpoint ещё не подтверждён, поэтому индикатор намеренно скрывается до получения реального ответа.

Работающий чат Ерохи и Telegram-бот менять не требуется. Для включения счётчика необходимо добавить только указанный endpoint в существующий публичный HTTPS API Ерохи.

## Согласованный контракт

**POST** `https://api.mudriakov.ru/v1/site-presence`

Заголовки:

```http
Origin: https://mudriakov.ru
Content-Type: application/json
```

Тело запроса:

```json
{"visitor_id":"a954aeeb-4897-4361-9635-5210491b7069","active":true}
```

- `visitor_id`: UUID v4, создаётся браузером и хранится в `sessionStorage` под ключом `mudriakov_presence_session_v1`; не является секретом и не подтверждает личность.
- `active:true`: отмечает эту браузерную сессию как активную.
- `active:false`: снимает отметку активности при переходе вкладки в фон или закрытии страницы.

Ожидаемый ответ на оба значения `active`:

```http
HTTP/1.1 200 OK
Content-Type: application/json
Cache-Control: no-store
```

```json
{"online":3}
```

`online` - неотрицательное целое число активных уникальных идентификаторов с последним успешным heartbeat не старше 45 секунд. Это приблизительный подсчёт **активных браузерных сессий**, а не достоверное количество уникальных людей.

## Алгоритм и экономия ресурсов

- Клиент отправляет heartbeat при открытии страницы и примерно раз в 15 секунд при видимой вкладке.
- При `visibilitychange` -> `hidden` клиент отправляет `active:false` с `keepalive:true`, затем прекращает heartbeat.
- При возвращении во вкладку heartbeat возобновляется; при восстановлении страницы из bfcache учитывается `pageshow`.
- Сервер должен считать сессию неактивной спустя 45 секунд отсутствия heartbeat, даже если запрос на завершение не дошёл.
- Хранить только UUID и время последнего heartbeat (например, одна компактная таблица в текущей PostgreSQL со строкой на сессию, `UPSERT` по UUID). `active:false` может удалить строку.
- Никаких новых записей аудита на каждое обновление, никаких записей истории просмотров, IP, User-Agent, адресов страниц или персональных данных в таблице присутствия.
- Старые записи удалять периодически, например раз в 5 минут, не при каждом heartbeat. Не создавать новую базу, Redis или контейнер только ради счётчика.
- Запросы не должны вызывать OpenAI и не должны иметь доступ к административным функциям Ерохи.
- CORS: только `https://mudriakov.ru` и корректный preflight OPTIONS. Не добавлять wildcard или другие Origins.
- Публичный endpoint следует считать недоверенным: валидировать UUID v4, ограничивать частоту и размер запросов, не принимать произвольные роли/поля, не использовать эту статистику как основание для финансовых или безопасностных решений.
- Использовать одну согласованную транзакцию на upsert/delete и count, насколько это позволяет выбранная СУБД. Учитывать конкурентные обновления.
- При ошибки endpoint сайт сохраняет работоспособность, а счётчик скрывается. При HTTP 404/405 фронтенд прекращает повторные обращения до новой загрузки страницы.

## Файлы frontend

- `index.html` - элемент `#site-live-visitors` в нижнем колонтитуле, подключения JS/CSS.
- `assets/js/site-presence.js` - heartbeat, видимость вкладки, показ реального числа, RU/EN через `document.documentElement.lang`.
- `assets/css/site-presence.css` - компактное оформление.

## Приёмка сервера

1. Первый видимый клиент -> `online:1`.
2. Две независимые браузерные сессии -> `online:2`.
3. Повтор heartbeat от того же UUID -> число не увеличивается.
4. `active:false` от одной сессии -> число уменьшается.
5. При обрыве связи сессия перестаёт учитываться после TTL.
6. Неверный UUID или повреждённый JSON -> корректный 4xx, без записи в БД.
7. `GET` на чужие endpoints, OpenAI, Telegram и админские API не затронуты.
8. CORS и HTTPS работают с `https://mudriakov.ru`.
9. Нет бесконечно растущей таблицы присутствия и потока логов на диск.
10. Существующие контейнеры, особенно Hot Potato, не затронуты.

**Важно:** для выполнения серверной части нужен отдельный доступ к текущим исходникам Ерохи и VPS. Данный коммит сайта не изменяет VPS и не доказывает работоспособность backend-счётчика.
